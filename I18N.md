# English support / 英文支持

Starforge follows the DST client language. English (`en`) selects English text;
Chinese remains the fallback for other or unavailable locale codes. Mod settings
follow the language supplied by DST's ModIndex. No additional language setting is required.

## Coverage

- Mod information, configuration choices, forge controls and dialogs.
- Affixes, gems, set bonuses, buffs, item and creature hover details.
- Registered mod items, creatures, eggs, treasure sites, recipes and descriptions.
- Custom item names, star upgrades and repairs, skin selectors, help and settings.
- Combat labels, treasure labels, job cards, equipment sharing and announcements.
- New structured world logs render in the viewing client's language.

Gameplay IDs, recipe values and save identifiers are shared between languages.
Player names and other user-authored text are preserved.

## Existing data and multiplayer behavior

- Logs saved before structured log data was introduced retain their original text.
- Shared speech bubbles use the speaking player's selected language. Equipment
  sharing, mod announcements, combat labels and new logs render per client.
- Unknown messages supplied by other mods retain their original text.
- The disabled, unfinished profession UI remains outside the enabled feature set.
  Its loaded item prefabs and job-card labels have English text.

## Validation

Lua 5.1 syntax checks and the regression suites cover translations, placeholders,
locale fallback, prefab coverage, dynamic names and existing gameplay fixes.
They use mocked game services. The v0.2.0 prerelease still needs in-game checks:

1. Join a test world with one English and one Chinese client.
2. Check the forge, hover panels, help, skins, shared items, combat and announcements.
3. Upgrade and repair a crown; check the displayed name and binding state.
4. Save, reload and verify items and both new and legacy world logs.
5. Check long English text at the game's supported UI scales.
